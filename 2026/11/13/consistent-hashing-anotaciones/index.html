Consistent hashing: anotaciones

Para asignar una clave a un servidor podemos usar hash(clave) % cantidad_de_nodos. El problema aparece al agregar o quitar servidores: cambia el divisor y muchas claves cambian de destino. Consistent hashing mantiene un espacio de posiciones fijo y coloca allí tanto nodos como claves.

Los ejemplos consish/ de nh35a comparten cuatro partes: calcular una posición, registrar los nodos, ordenarlos y buscar el siguiente nodo del anillo.

Del hash al anillo

En Zig, hashS obtiene un digest MD5 de 16 bytes, lee sus dos mitades como enteros de 64 bits en big endian y las combina mediante XOR:

fn hashS(s: []const u8, ns: u64) u64 {
    var d: [16]u8 = undefined;
    std.crypto.hash.Md5.hash(s, &d, .{});

    const dl = std.mem.readInt(u64, d[0..8], .big);
    const dh = std.mem.readInt(u64, d[8..16], .big);

    return (dh ^ dl) % ns; // posición dentro del anillo
}

Aquí ns = 65535: las posiciones van de 0 a 65534. Es el tamaño del anillo, independiente de cuántos nodos haya. Todos deben usar el mismo hash y la misma interpretación de los bytes para reproducir la asignación.

En Nodes, ds guarda nombres y ss sus posiciones. add incorpora ambos; done los ordena por posición, manteniendo cada nombre junto a su hash. Con los nodos del ejemplo, el orden es B:8630, A:14321, C:35588.

Buscar el nodo responsable

Cada nodo recibe las claves del intervalo que termina en su posición. La búsqueda encuentra el primer hash mayor o igual al de la clave. Si no existe, vuelve al comienzo del anillo:

fn bs(self: *const Nodes, s: []const u8) struct { []const u8, u64 } {
    if (self.ss.items.len == 0) @panic("no elements");

    const sh = hashS(s, self.ns);
    var i = std.sort.lowerBound(u64, self.ss.items, sh, cmpHash);

    if (i == self.ss.items.len) {
        i = 0; // vuelta al primer nodo
    }

    return .{ self.ds.items[i], sh };
}

Con las posiciones ordenadas, la búsqueda binaria cuesta O(log N) para N nodos, además del cálculo del hash. El segundo valor retornado, sh, es la posición de la clave, no la del nodo elegido.

Qué cambia al agregar un nodo

La clave "10" cae en 41300, después de C; por eso vuelve a B. Si incorporamos D, cuyo hash es 50913, pasa a tener un sucesor antes de completar la vuelta:

ClaveHashSin DCon D
"1"21135CC
"10"41300BD
"100"19522CC

Este agregado extiende el ejemplo original. Solo las posiciones del intervalo (35588, 50913] pasan de B a D; el resto conserva su propietario. Esa estabilidad al cambiar los nodos es la idea central. En la versión Zig, el ejemplo ampliado requiere inicializar Nodes con capacidad para cuatro elementos, porque add usa appendBounded.

Las partes comunes en cada lenguaje

  • C: implementa MD5 y guarda nombres y hashes en arrays paralelos. done usa inserción; la búsqueda binaria es manual. Duplica los nombres y libera la memoria explícitamente.
  • C++: también implementa MD5. Usa vectores, ordena los pares con stable_sort sobre zip y busca con lower_bound. Los contenedores gestionan su memoria.
  • C3: usa MD5 de la biblioteca estándar y listas paralelas. Construye pares temporales para ordenar con quicksort y consulta mediante binarysearch como punto de inserción.
  • Go: usa crypto/md5 y binary.BigEndian. sort.Interface intercambia juntos nombres y hashes; slices.BinarySearch encuentra el nodo o su punto de inserción.
  • OCaml: usa Digest y un array de pares. Ordena y calcula el módulo con operaciones sin signo sobre int64; implementa la búsqueda mediante recursión.
  • Rust: usa el crate md-5 y vectores paralelos. Ordena índices para reordenar ambos vectores; partition_point encuentra el primer hash que no sea menor.
  • Swift: usa CryptoKit.Insecure.MD5, enteros UInt64 y un array de tuplas. sort conserva unidos nombre y posición; la búsqueda binaria es manual.
  • Zig: usa Md5, ArrayList y un allocator explícito. heapContext ordena intercambiando ambas listas; lowerBound resuelve la búsqueda.

Estos ejemplos colocan un solo punto por nodo, por lo que los intervalos pueden ser desiguales. Los nodos virtuales permiten distribuir cada servidor entre varios puntos del anillo. Las colisiones también requieren una regla compartida de desempate para conservar una asignación reproducible.
